# US-000: Регистрация и Авторизация

## Описание модуля

Пользователь регистрируется или входит в PipelineHQ через **Threads (Meta OAuth)** или **Gmail (Google OAuth)**. После успешной авторизации система определяет, новый ли это пользователь или существующий, и направляет его соответственно — в онбординг или на Dashboard.

## Концепция: "Вход за 10 секунд"

Никаких форм с email/паролем. Только социальный вход — минимум трения.

- **Threads** — основной способ входа (сразу даёт доступ к API Threads для анализа контента)
- **Gmail** — альтернативный вход (для тех, кто ещё не в Threads или хочет сначала посмотреть продукт)

### Флоу регистрации

```
Landing Page → "Войти через Threads" / "Войти через Gmail" → OAuth → Создание аккаунта → Onboarding (US-001)
```

### Флоу повторного входа

```
Landing Page → "Войти через Threads" / "Войти через Gmail" → OAuth → Dashboard
```

## User Stories

### US-000.1 — Регистрация через Threads

**Как** новый пользователь,  
**я хочу** зарегистрироваться через свой аккаунт Threads,  
**чтобы** войти в систему и сразу подключить свой контент для анализа.

**Acceptance Criteria:**
- [x] Кнопка "Войти через Threads" на экране входа
- [x] Клик → редирект на Meta OAuth (scope: `threads_basic`, `threads_content_publish`, `threads_manage_insights`)
- [x] После успешной авторизации → создание аккаунта в БД (user + связанный Threads account)
- [x] Сохранение `access_token` и `refresh_token` Threads API в БД
- [x] Redirect → Onboarding (US-001), шаг подключения Threads уже пройден
- [x] Если пользователь с таким Threads ID уже существует → логин (не дублирование)
- [x] Обработка ошибок: пользователь отменил OAuth → возврат на экран входа с сообщением

---

### US-000.2 — Регистрация через Gmail

**Как** новый пользователь,  
**я хочу** зарегистрироваться через свой Gmail-аккаунт,  
**чтобы** войти в систему, даже если я ещё не пользуюсь Threads активно.

**Acceptance Criteria:**
- [x] Кнопка "Войти через Gmail" на экране входа
- [x] Клик → редирект на Google OAuth (scope: `email`, `profile`)
- [x] После успешной авторизации → создание аккаунта в БД (user + связанный Google account)
- [x] Сохранение email и имени пользователя из Google-профиля
- [x] Redirect → Onboarding (US-001), начиная с шага подключения Threads (Threads ещё не подключён)
- [x] Если пользователь с таким email уже существует → логин (не дублирование)
- [x] Обработка ошибок: пользователь отменил OAuth → возврат на экран входа с сообщением

---

### US-000.3 — Привязка Threads к Gmail-аккаунту

**Как** пользователь, зарегистрированный через Gmail,  
**я хочу** позже привязать свой профиль Threads,  
**чтобы** система могла анализировать мой контент и предоставить полный функционал.

**Acceptance Criteria:**
- [ ] В онбординге (US-001.1) и в настройках профиля — кнопка "Подключить Threads"
- [ ] OAuth-флоу Meta → связывание Threads-аккаунта с существующим пользователем
- [ ] Сохранение `access_token` и `refresh_token` Threads API
- [ ] После привязки → доступ к Smart Onboarding с автозаполнением
- [ ] Если Threads-аккаунт уже привязан к другому пользователю → ошибка с пояснением

---

### US-000.4 — Повторный вход (логин)

**Как** существующий пользователь,  
**я хочу** войти в систему через тот же метод, что и при регистрации,  
**чтобы** быстро попасть к своим данным.

**Acceptance Criteria:**
- [x] Те же кнопки: "Войти через Threads" и "Войти через Gmail"
- [x] OAuth → проверка: пользователь существует → создание сессии
- [x] Redirect → Dashboard (если онбординг пройден) или Onboarding (если не пройден)
- [x] Обновление `access_token` при каждом входе (если токен обновился)
- [x] Если пользователь не найден → автоматическая регистрация (seamless)

---

### US-000.5 — Экран входа

**Как** посетитель,  
**я хочу** видеть понятный и красивый экран входа,  
**чтобы** сразу понимать, как войти в сервис.

**Acceptance Criteria:**
- [x] Лого PipelineHQ
- [x] Заголовок: ценностное предложение ("Превратите Threads в машину продаж")
- [x] Кнопка "Войти через Threads" — основная (primary), с иконкой AtSign
- [x] Кнопка "Войти через Gmail" — вторичная (outline), с иконкой Mail
- [x] Подпись: "Регистрируясь, вы соглашаетесь с Условиями использования и Политикой конфиденциальности"
- [x] Ссылки на Terms of Service и Privacy Policy
- [x] Mobile-first, responsive дизайн
- [ ] Тёмная тема (соответствует design system)

---

### US-000.6 — Управление сессией

**Как** авторизованный пользователь,  
**я хочу** оставаться залогиненным между визитами,  
**чтобы** не проходить авторизацию каждый раз.

**Acceptance Criteria:**
- [x] Сессия сохраняется в БД (Better Auth database sessions)
- [x] Сессия живёт 30 дней (с обновлением при активности каждые 24h)
- [x] При истечении сессии → редирект на экран входа
- [x] Кнопка "Выйти" в sidebar (UserMenu)
- [x] Выход → удаление сессии на сервере → редирект на экран входа
- [x] Защита роутов: все страницы кроме `/login` требуют авторизации (middleware)

---

### US-000.7 — Безопасность и хранение токенов

**Как** пользователь,  
**я хочу** быть уверенным, что мои данные защищены,  
**чтобы** доверять сервису доступ к моему Threads-аккаунту.

**Acceptance Criteria:**
- [ ] `access_token` и `refresh_token` Threads хранятся в БД в зашифрованном виде
- [x] Token exchange: short-lived → long-lived token (60 дней) при авторизации через Threads
- [ ] Token refresh: при истечении access_token — автоматическое обновление через refresh_token
- [ ] При ошибке refresh → уведомление пользователю "Переподключите Threads"
- [x] Google tokens НЕ сохраняются долгосрочно (нужны только для аутентификации)
- [x] CSRF-защита на OAuth callback endpoints (Better Auth встроенная)
- [ ] Rate limiting на auth endpoints (защита от брутфорса)

## Логика маршрутизации после авторизации

```
OAuth Callback
  ├── Новый пользователь → Onboarding (US-001)
  │     ├── Вход через Threads → Onboarding, шаг "Подключи Threads" = ✅ (уже подключён)
  │     └── Вход через Gmail → Onboarding, шаг "Подключи Threads" = предложение подключить
  └── Существующий пользователь
        ├── Онбординг не завершён → Onboarding, последний шаг
        └── Онбординг завершён → Dashboard
```
